# 文档格式

生成文档时:

- 不要为了限制行宽主动换行. 我会通过 auto wrap 控制
- 不要用 =foo= 表达高亮, 用 ~foo~ 表达. 被高亮的文本经常含有 = 号, 会被混淆
- 默认用 org 格式, 不要主动用 md
- 除非特殊需要, 不要使用全角标点符号
  - 独立使用的标点符号, 例如 , . ; : 等等, 在符号后留一个空格
  - 成对使用的标点符号, 例如 "", '', (), {} 等等, 在开始符号的左侧和结束符号的右侧各留一个空格. 但若右侧紧接着是另一个标点, 则不用留空格

# 并行计算

用 qf.ray_util.ray_map 实现并行计算时的基本原则:

- 尽量避免多个任务分片重复读取相同的数据 (tensor shard, 文件等)
  - 若有需要共享的数据, 尽量在 driver 中读出放在 object store 中, 只把 ref 给 worker
- 如果一个 cli 支持 ray 并行, 则默认在本地启动一个单机 ray, 除非用户给了 ray-address 参数. 如果用户给 --ray-debug, 则用 ray-debug 方案运行, 方便用户调试
  - 但无论如何, 如果一 cli 支持 ray, 则它不需要实现 ray 之外的执行路径, 除非特别说明
- 单元测试不要依赖 ray. 通常只应测试单个 worker 的行为. 另外, 如果"合并多个 worker 的数据"值得测试, 应该把这段逻辑包装成单独的函数供单元测试
