# 语言风格

- 对用户提出的所有需求, 默认只评估, 不执行. 只有当用户在一句话中明确给出"执行此任务"或类似指令时才执行
  - 例如, 用户指出"这个图的横坐标 label 需要旋转 90 度", 此时只评估, 不执行. 如果用户单独回复"执行此任务", 或直接在 prompt 中说"这个图的横坐标 label 需要旋转 90 度, 立即执行"时, 才真的执行任务, 修改文件

# Agent output

Agent 的输出中:

- latex 公式必须全 ascii 字符, 不要在其中使用中文或其它非 ascii 字符

# DVC

如果一个目录或文件有 .dvc 文件对应, 则不应修改它. 例如若存在文件 foo.dvc, 则不应修改 foo 文件, 或在 foo 目录中修改/添加/删除任何内容

# 文档格式

生成文档时:

- 不要为了限制行宽主动换行. 我会通过 auto wrap 控制
- 不要用 =foo= 表达高亮, 用 ~foo~ 表达. 被高亮的文本经常含有 = 号, 会被混淆
- 默认用 org 格式, 不要主动用 md
- 除非特殊需要, 不要使用全角标点符号
  - 独立使用的标点符号, 例如 , . ; : 等等, 在符号后留一个空格
  - 成对使用的标点符号, 例如 "", '', (), {} 等等, 在开始符号的左侧和结束符号的右侧各留一个空格. 但若右侧紧接着是另一个标点, 则不用留空格
    - 这是一个 (关于标点符号) 的示例
    - 这是一个 (示例), 展示了结束符号右侧紧接其它标点的情况
- 文档中若有需要用户回答的问题, 可提出, 并在"答复"后开一个空的 org comment block, 回复会填写在其中
- 用户也可能在任何位置用 org comment block 添加上下文相关的评论
- org 文档头需要添加 local variable 设定如下:
  - org-use-sub-superscripts: "{}"
- org 头部的 local variable 必须使用如下格式

```
# Local Variables:
# org-use-sub-superscripts: "{}"
# End:
```

# 并行计算

用 qf.ray_util.ray_map 实现并行计算时的基本原则:

- 尽量避免多个任务分片重复读取相同的数据 (tensor shard, 文件等)
  - 若有需要共享的数据, 尽量在 driver 中读出放在 object store 中, 只把 ref 给 worker
- 如果一个 cli 支持 ray 并行, 则默认在本地启动一个单机 ray, 除非用户给了 ray-address 参数. 如果用户给 --ray-debug, 则用 ray-debug 方案运行, 方便用户调试
  - 但无论如何, 如果一 cli 支持 ray, 则它不需要实现 ray 之外的执行路径, 除非特别说明
- 单元测试不要依赖 ray. 通常只应测试单个 worker 的行为. 另外, 如果"合并多个 worker 的数据"值得测试, 应该把这段逻辑包装成单独的函数供单元测试
- max_in_flight 控制同时提交给 ray 的最大任务数, 不是控制 ray 并行执行的任务数. 此参数的意义在于减少 ray scheduler 的调度负担. 通常采用默认值即可, 除非用户特别指定, 不要设定此参数
